wearebase system architecture

17 November 2026

Summary

One version store, one gateway, and two new products on the same payment rails: a trading feed and data-centre site intelligence. Maritime stays as it is. Everything is built from external data only, with no tenant input.

  • The moat is history. NESO and weather forecasts are overwritten upstream; every version we keep exists nowhere else.
  • One set of payment rules for every product: x402 per call, GBP credits, x402 sessions, never charged for stale or undelivered data.
  • Today: NESO grid (6 datasets) and maritime run on staging. Prices, Environment Agency, weather and site risk are planned.

Architecture

Data flows down: external sources into the ingest services, into one append-only store, out through one gateway whose kernel applies the same payment rules to every product.

Decisions (17 November 2026)

  1. Site-intelligence buyers pay through the same rails (x402, credits, sessions); no separate subscription.
  2. A site comes from our list of known UK data-centre locations, not buyer-submitted coordinates.
  3. Prices (Elexon) are for all products: the trading feed and site intelligence.
  4. Maritime stays separate from both new products.
